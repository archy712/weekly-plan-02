## 주요 기능

- **주간업무일지 CRUD** — 시작일/목표종료일/업무명/업무 상세 내용(리치 텍스트 에디터, +예상 M/M·예상 금액(3자리 콤마 자동 삽입)·협력사, 모두 선택 입력)으로 업무를 기록·수정·삭제
- **업무 타입 다중 분류(v1)** — 관리자가 관리하는 업무 타입(조직별로 독립된 목록) 중 1개 이상을 체크박스로 다중 선택. 상세 페이지에서는 진행상태와 동일하게 별도 수정 모드 없이 체크/해제만으로 즉시 반영
- **업무 중요도(v1)** — 슬라이더로 1~5단계(매우낮음~매우높음) 지정, 상세 페이지에서는 슬라이더 조작만으로 즉시 반영
- **첨부파일 업로드** — 작성/수정 화면에서 파일당 최대 5MB 첨부파일을 업로드(파일별 진행률 표시, 5MB 초과 시 즉시 거부), 상세 페이지에서 다운로드·삭제
- **진행상태 추적** — 예정/진행중/완료 3단계 상태 전환
- **부서 기반 접근 제어** — 조회는 로그인한 모든 사용자에게 부서 무관하게 공개, 쓰기(작성/수정/삭제/진행상태변경)는 작성자의 소속 부서 또는 관리자로 제한
- **검색·필터·정렬·페이징** — 제목/내용 키워드 검색, 부서 필터(기본값은 일반 사용자는 자기 부서·관리자는 전체), 기간 범위 필터(v1, "이번 주/이번 달/최근 3개월" 프리셋), 모든 컬럼 헤더 클릭으로 정렬, 무한 스크롤 페이징, 현재 필터 조건에 맞는 **총 건수 표시**(v1 ad hoc, 주간업무목록·관리자 사용자 관리)
- **PDF·Excel 리포팅** — 현재 조회 중인 목록(적용된 필터 포함)을 표 형태 PDF(한글 폰트 임베딩) 또는 Excel(.xlsx, v1 — 업무타입·중요도·예상소요기간/금액·협력업체·내용까지 포함)로 다운로드
- **인증** — 이메일/비밀번호 회원가입·로그인(가입 즉시 로그인) + 구글 OAuth 소셜 로그인
- **부서 선택 온보딩** — 로그인 직후 부서 미설정 시 다른 모든 보호 페이지 접근을 프로필 페이지로 유도
- **프로필 상세 정보** — 이름(최대 50자)·전화번호(숫자만 입력해도 `010-1234-5678` 형식으로 하이픈 자동 삽입)·프리셋 아바타(이모지 24종을 팝업 다이얼로그에서 택1)·자기소개(최대 500자) 입력을 프로필 화면과 회원가입 화면에서 지원, 선택한 아바타는 공통 헤더의 이메일 앞에도 표시
- **조직(organizations) 계층(v1)** — 모든 부서는 반드시 하나의 조직에 속하며, 헤더 타이틀과 로그인 상태의 랜딩 CTA에 소속 조직명이 동적으로 표시됨(예: "IT부문 주간업무")
- **관리자 콘솔(v1)** — 대시보드·조직 관리·부서 관리·업무타입 관리·사용자 관리 5개 탭으로 구성되며 공통 헤더의 "관리자 콘솔" 링크로만 진입(관리자 전용). **일반 관리자(`admin`)는 모든 탭이 자기 소속 조직 범위로 제한**된다(소속 부서로 자동 결정). 대시보드는 부서별·기간별·상태별·업무 타입별·중요도별 업무 현황을 요약 카드 4종·차트 6종(막대/조각별 비율·수치 라벨, 중요도 레이더 포함)으로 시각화하고, 조직 관리는 자기 조직 1건의 이름 수정·비활성화만 가능한 단일 카드, 부서 관리는 부서 추가·이름 변경·비활성화(소프트 삭제, 부서원·업무일지가 있으면 하드 삭제 자동 차단), 업무타입 관리는 조직별로 독립된 업무 타입을 동일한 CRUD 패턴으로 관리, 사용자 관리는 조직 범위 내 사용자를 검색·필터·정렬로 조회해 역할(`user`/`admin`/`superadmin`)과 소속 부서를 변경(자기 강등 방지, 재로그인 없이 즉시 권한 반영). **`admin` 위에는 슈퍼관리자(`superadmin`) 등급이 있다**(승격은 이미 `admin`인 사용자만 가능) — 조직 관리 탭에서 시스템의 모든 조직을 나열·생성할 수 있고, 나머지 4개 탭도 전 조직 범위로 확장되어 조직 경계 없이 조회·관리할 수 있다
- **주간업무일지 목록의 작성자 표시(ad hoc)** — 목록(테이블·카드)의 부서 배지를 작성자의 프리셋 아바타 + 이름(또는 이메일)으로 대체해 담당자를 한눈에 파악할 수 있다. 정렬 기준도 부서명 대신 작성자명 기준이며, 부서 정보 자체는 상세 페이지·부서 필터·PDF/Excel 다운로드에 계속 노출된다
- **댓글·멘션 협업(v1)** — 상세 페이지에서 plain text 댓글 작성(1단계 대댓글, 소프트 삭제)과 `@` 멘션 검색·삽입을 지원(부서 무관하게 모든 로그인 사용자가 작성 가능, 수정·삭제는 작성자 본인 또는 관리자로 제한). 댓글이 있는 주간업무일지는 목록 페이지 제목 옆에도 댓글수가 함께 표시됨
- **추천/비추천(v1)** — 상세 페이지에서 개별 주간업무일지에 추천/비추천을 남길 수 있음(댓글과 동일하게 부서 무관, **1인 1표**이며 같은 버튼 재클릭 시 해제·반대 버튼 클릭 시 전환, 낙관적 업데이트). 자기 글에도 반응 가능하고 관리자 예외 없이 본인 행만 조작되며, 목록 페이지와 관리자 대시보드에는 익명 집계만 표시됨(투표자 명단 비공개)
- **실시간 알림(v1)** — 자신이 멘션되거나 자신이 쓴 글에 댓글·답글이 달리면 새로고침 없이 공통 헤더의 알림 벨(안 읽은 개수 배지)에 즉시 표시(Supabase Realtime). 클릭 시 해당 댓글 위치로 이동해 읽음 처리되며, 실시간 연결이 끊겨도 폴링으로 조용히 폴백해 앱 사용에 지장이 없음
- **정보/쇼케이스 페이지(v1, ad hoc)** — 공통 푸터에서 프로젝트 문서(README·PRD)·로드맵(MVP·v1) 링크와 함께 앱 내부 정보 페이지 3종으로 진입: 컴포넌트 갤러리(shadcn Base UI 카탈로그), 아이콘 갤러리(lucide 실물 렌더링), 기술 스택(`package.json` 기반, npm 최신 vs 설치 버전 비교). 세 페이지 모두 비로그인 공개
- **다크모드 토글 · 반응형 레이아웃**(데스크탑/태블릿/모바일, 관리자 콘솔 테이블 포함)

기능별 상세 명세는 [`docs/PRD.md`](docs/PRD.md)를 참고하세요. 위 v1 고도화 기능과 이후 사용자 요청으로 추가된 주간업무일지 추천/비추천(F031)·애플리케이션 전반 성능 개선(F032)까지 모두 구현 완료됐으며(성능 개선은 인증 계정이 필요한 E2E 회귀 검증만 사용자 작업으로 대기), 개발 이력과 성능 측정 결과는 [`docs/ROADMAP_v1.md`](docs/ROADMAP_v1.md)에서 확인할 수 있습니다.

## 기술 스택

- **Next.js 16** (App Router) + **React 19** + **TypeScript**
- **Supabase** — Auth(이메일/비밀번호 + 구글 OAuth), PostgreSQL(Row Level Security), Storage(첨부파일, 서명 URL 기반 업로드/다운로드), `@supabase/ssr` 쿠키 기반 세션
- **Tailwind CSS v4** + **shadcn/ui**(`new-york` 스타일), **next-themes** 다크모드
- **React Hook Form** + **Zod** 폼 검증
- **Tiptap** — 업무 상세 내용용 WYSIWYG 리치 텍스트 에디터, **DOMPurify**(`isomorphic-dompurify`)로 저장·렌더링 이중 sanitize
- **jsPDF** + **jspdf-autotable** — 클라이언트 사이드 PDF 생성
- **exceljs**(v1) — 클라이언트 사이드 Excel(.xlsx) 생성
- **shadcn `chart` + Recharts**(v1) — 관리자 콘솔 통계 대시보드 차트(레이더 포함)
- **Supabase Realtime**(v1) — `notifications` 테이블 Postgres Changes 구독으로 헤더 알림 벨 실시간 갱신(브라우저 클라이언트 전용, 연결 끊김 시 폴링 폴백)

아키텍처와 관례에 대한 상세 가이드는 [`CLAUDE.md`](CLAUDE.md)와 [`docs/guides/`](docs/guides/)를 참고하세요.

## 로컬 개발 환경 설정

1. 이 저장소를 클론합니다.

   ```bash
   git clone <repository-url>
   cd weekly-plan-02
   npm install
   ```

2. [Supabase 프로젝트](https://database.new)를 생성하고 프로젝트 루트에 `.env.local`을 만들어 아래 두 값을 채웁니다.

   ```env
   NEXT_PUBLIC_SUPABASE_URL=[프로젝트 URL]
   NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=[프로젝트 API publishable/anon 키]
   ```

   두 값은 [Supabase 프로젝트의 API 설정](https://supabase.com/dashboard/project/_?showConnect=true)에서 확인할 수 있습니다. 값이 없으면 `hasEnvVars`가 `false`가 되어 UI가 경고 모드로 폴백합니다.

3. 개발 서버를 실행합니다.

   ```bash
   npm run dev     # http://localhost:3000
   ```

### 자주 쓰는 명령어

```bash
npm run dev     # 개발 서버
npm run build   # 프로덕션 빌드
npm run start   # 프로덕션 서버 실행
npm run lint    # ESLint 검사
npx tsc --noEmit  # 타입 체크(별도 스크립트 없음)
```

DB 스키마 마이그레이션, RLS 정책, 관리자 계정 지정, 부서 seed 데이터 등 운영 관련 절차는 [`docs/guides/deployment-ops.md`](docs/guides/deployment-ops.md)에 정리되어 있습니다.
