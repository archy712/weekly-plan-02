# 부서별 주간업무일지 관리 웹 애플리케이션 MVP PRD

## 🎯 핵심 정보

**목적**: 부서원들이 한 곳에서 주간 업무 진행 상황을 기록·추적하고, 관리자는 모든 부서의 업무 현황을 한눈에 파악할 수 있게 한다.
**사용자**: 여러 부서로 구성된 조직의 실무자(부서 소속 일반 사용자)와 전체 부서 현황을 관리하는 관리자.

## 🚶 사용자 여정

```
1. 랜딩 페이지
   ├─ [로그인] 버튼 클릭 ──────────────┐
   └─ [회원가입] 버튼 클릭 ─────┐       │
                              ↓       ↓
                     2. 회원가입 페이지   2. 로그인 페이지
                     - 이메일/비밀번호     - 이메일/비밀번호 로그인
                       입력 후 가입         또는 [구글로 계속하기]
                     ↓ 가입 성공
                     이메일 인증 메일 발송
                     → 메일 링크 클릭
                     → 인증 완료             ↓ 로그인 성공
                     ↓                       │
                     로그인 페이지로 이동 ──────┘
                              ↓
              3. 인증 상태 자동 확인 (부서 설정 여부 체크)

     [부서 미설정] → 4. 프로필 페이지(온보딩)         [부서 설정됨]
                     - 부서 선택 후 저장 ───────────────────┐
                     (저장 전까지 다른 페이지 접근 차단)       ↓
                                                  5. 주간업무일지 목록 페이지
                                                     (자기 부서 / 관리자는 부서 필터로 전체)
                     ↓ [신규 작성]        ↓ 항목 클릭         ↓ [PDF 다운로드]
              6. 작성 페이지         7. 상세 페이지          PDF 파일 다운로드
                 - 입력 후 저장        - 조회/수정/완료처리/삭제  (목록 페이지 유지)
                     ↓ 저장 성공          ↓ 완료
                     └──────── 5. 주간업무일지 목록 페이지로 복귀 ────────┘
```

- 부서 미설정 상태에서는 `주간업무일지 목록/작성/상세` 등 모든 보호된 페이지 접근이 자동으로 **프로필 페이지**로 리디렉션된다.
- 이메일/비밀번호 찾기 등 기존 스타터킷의 인증 보조 흐름(비밀번호 재설정 등)은 본 PRD 범위에서 변경하지 않고 그대로 유지한다.

## ⚡ 기능 명세

### 1. MVP 핵심 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |
|----|--------|------|-------------|------------|
| **[F001]** | 주간업무일지 목록 조회 | 자기 부서(관리자는 선택한 부서)의 주간업무일지를 제목/기간/완료상태와 함께 리스트로 조회 | 서비스의 핵심 진입점, 업무 현황 파악의 기본 기능 | 주간업무일지 목록 페이지 |
| **[F002]** | 주간업무일지 상세 조회 | 개별 주간업무일지의 시작일/목표종료일/제목/본문/완료여부를 상세히 조회 | 기록된 업무 내용을 정확히 확인하기 위한 필수 기능 | 주간업무일지 상세 페이지 |
| **[F003]** | 주간업무일지 신규 작성 | 시작일/목표종료일/제목/본문을 입력해 새 주간업무일지를 등록 | 업무 기록의 시작점, 서비스의 존재 이유 | 주간업무일지 작성 페이지 |
| **[F004]** | 주간업무일지 수정 | 기존 주간업무일지의 내용을 수정 | 진행 상황 변경을 반영하기 위한 필수 기능 | 주간업무일지 상세 페이지 |
| **[F005]** | 주간업무일지 삭제 | 잘못 작성되었거나 불필요한 주간업무일지를 삭제 | 데이터 정합성 유지를 위한 최소 관리 기능 | 주간업무일지 상세 페이지 |
| **[F006]** | 완료 처리 | 주간업무일지를 완료/미완료 상태로 전환 | 업무 진행 여부를 구분하는 핵심 비즈니스 로직 | 주간업무일지 상세 페이지 |
| **[F007]** | 관리자 전체 부서 조회 | 관리자가 부서 필터를 이용해 모든 부서의 주간업무일지를 조회 | 관리자의 전체 현황 파악이라는 핵심 요구사항 | 주간업무일지 목록 페이지 |
| **[F008]** | 부서별 리스트 PDF 다운로드 | 현재 조회 중인 부서의 주간업무일지 리스트를 PDF 파일로 다운로드 | 보고/공유를 위한 필수 리포팅 기능 | 주간업무일지 목록 페이지 |

### 2. MVP 필수 지원 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |
|----|--------|------|-------------|------------|
| **[F010]** | 기본 인증 | 이메일/비밀번호 회원가입, 로그인, 로그아웃 | 서비스 이용을 위한 최소 인증 | 로그인 페이지, 회원가입 페이지 |
| **[F011]** | 구글 소셜 로그인 | 구글 계정으로 OAuth 로그인/회원가입 | 사용자 편의를 위한 필수 로그인 수단 | 로그인 페이지 |
| **[F012]** | 부서 선택 온보딩 | 프로필 화면에서 소속 부서를 선택/변경, 미선택 시 서비스 이용 차단 | 모든 업무일지 기능이 부서 단위로 동작하기 위한 전제 조건 | 프로필 페이지 |
| **[F013]** | 다크모드 토글 | 라이트/다크 테마를 전환 | 요청된 필수 UI 요구사항 | 전체 페이지(공통 헤더) |
| **[F014]** | 반응형 레이아웃 | 데스크탑/태블릿/모바일 화면 대응 | 요청된 필수 UI 요구사항 | 전체 페이지(공통) |
| **[F015]** | 랜딩 기능 소개 카드 | 주요 기능을 카드 형식으로 소개 | 요청된 필수 랜딩 페이지 요구사항 | 랜딩 페이지 |

### 3. MVP 이후 기능 (제외)

- 부서 관리(부서 추가/수정/삭제) UI — 부서는 초기 데이터로만 관리
- 관리자 역할 지정/변경 UI — role 컬럼은 DB에서 수동 관리
- 주간업무일지 고급 검색/필터(키워드, 기간 범위 등)
- 댓글, 멘션 등 협업 기능
- 첨부파일 업로드
- 실시간 알림 시스템
- 프로필 상세 관리(아바타, 자기소개 등)
- 통계/대시보드 차트

```
📱 부서별 주간업무일지 관리 내비게이션

🌐 공통 헤더 (비로그인 시)

│   └── 기능: F010 (이메일 회원가입)

    └── 기능: F013

👤 일반 사용자 메뉴 (로그인 후, 부서 설정 완료 시)
└── 📋 주간업무일지 목록
    └── 기능: F001 (자기 부서 리스트 조회, 신규작성/상세 진입점)

🛠️ 관리자 메뉴 (로그인 후, role=admin)
└── 📋 주간업무일지 목록 (부서 필터 포함)
    └── 기능: F001, F007 (전체 부서 조회)

🔧 공통 메뉴 (모든 로그인 사용자)
├── 👤 프로필
│   └── 기능: F012 (부서 선택/변경)
├── 🌓 다크모드 토글
│   └── 기능: F013
└── 🚪 로그아웃
```

일반 사용자와 관리자는 동일한 **주간업무일지 목록 페이지**를 사용하며, `role`에 따라 부서 필터 노출 여부(F007)만 달라진다.

## 📄 페이지별 상세 기능

### 랜딩 페이지

> **구현 기능:** `F015`, `F013`, `F014` | **메뉴 위치:** 공통 헤더 홈

| 항목 | 내용 |
|------|------|
| **역할** | 방문자에게 서비스의 핵심 가치와 주요 기능을 카드 형식으로 소개하는 랜딩 페이지 |
| **진입 경로** | 비로그인 상태로 최초 접속 시 기본 진입, 로그아웃 후 자동 이동 |
| **사용자 행동** | 기능 소개 카드를 확인하고 로그인 또는 회원가입 버튼을 클릭 |
| **주요 기능** | • 주요 기능 소개 카드(주간업무일지 작성/조회, 부서별 관리, 완료 상태 추적, PDF 다운로드) 노출<br>• 다크모드 토글<br>• 반응형 레이아웃(데스크탑/태블릿/모바일)<br>• **[로그인]** / **[회원가입]** 버튼 |
| **다음 이동** | [로그인] → 로그인 페이지, [회원가입] → 회원가입 페이지 |

### 로그인 페이지

> **구현 기능:** `F010`, `F011`, `F013`, `F014` | **인증:** 비로그인 전용

| 항목 | 내용 |
|------|------|
| **역할** | 이메일/비밀번호 또는 구글 계정으로 로그인하는 인증 전용 페이지 |
| **진입 경로** | 랜딩 페이지에서 로그인 버튼 클릭, 비로그인 상태로 보호된 페이지 접근 시 자동 리디렉션, 회원가입 후 이메일 인증 완료 시 이동 |
| **사용자 행동** | 이메일/비밀번호를 입력해 로그인하거나 [구글로 계속하기] 클릭 |
| **주요 기능** | • 이메일/비밀번호 로그인<br>• 구글 소셜 로그인(OAuth)<br>• 로그인 오류 메시지 표시<br>• 회원가입 페이지 이동 링크 |
| **다음 이동** | 성공(부서 미설정) → 프로필 페이지, 성공(부서 설정됨) → 주간업무일지 목록 페이지, 실패 → 에러 표시 |

### 회원가입 페이지

> **구현 기능:** `F010`, `F013`, `F014` | **인증:** 비로그인 전용

| 항목 | 내용 |
|------|------|
| **역할** | 이메일/비밀번호로 신규 계정을 생성하는 인증 전용 페이지 |
| **진입 경로** | 랜딩 페이지 또는 로그인 페이지에서 회원가입 링크 클릭 |

| **주요 기능** | • 이메일/비밀번호 회원가입<br>• 입력값 유효성 검사<br>• 가입 후 이메일 인증 안내 표시<br>• 로그인 페이지 이동 링크 |
| **다음 이동** | 성공 → 이메일 인증 안내 표시(메일 링크 클릭 시 로그인 페이지로 이동), 실패 → 에러 표시 |

### 프로필 페이지

> **구현 기능:** `F012`, `F013`, `F014` | **인증:** 로그인 필수

| 항목 | 내용 |
|------|------|
| **역할** | 소속 부서를 선택/변경하는 페이지이며, 부서 미설정 사용자에게는 온보딩 화면 역할을 겸함 |
| **진입 경로** | 로그인 직후 부서가 미설정이면 다른 모든 보호 페이지 접근이 이 페이지로 자동 리디렉션됨, 공통 메뉴의 [프로필]에서 언제든 진입 가능 |
| **사용자 행동** | 소속 부서를 드롭다운에서 선택하고 저장(부서 미설정 상태에서는 저장 전까지 다른 페이지로 이동 불가) |
| **주요 기능** | • 부서 선택 드롭다운(필수 입력)<br>• 부서 저장<br>• 부서 미설정 시 다른 기능 접근 차단 안내 문구<br>• 계정 기본 정보(이메일) 표시<br>• **[저장]** 버튼 |
| **다음 이동** | 저장 성공 → 주간업무일지 목록 페이지, 이미 부서가 설정된 경우 변경 후에도 같은 페이지 유지 |

### 주간업무일지 목록 페이지

> **구현 기능:** `F001`, `F007`, `F008`, `F013`, `F014` | **인증:** 로그인 + 부서 설정 필수

| 항목 | 내용 |
|------|------|
| **역할** | 자신의 부서(관리자는 전체 부서) 주간업무일지를 한눈에 확인하는 대시보드이자 관리 흐름의 시작점 |
| **진입 경로** | 로그인 후 부서 설정이 완료된 상태에서 자동/메뉴 이동으로 진입, 공통 메뉴에서 상시 접근 |
| **사용자 행동** | 목록을 확인하고 항목을 클릭하거나, 신규 작성 버튼을 클릭하거나, (관리자) 부서 필터를 변경하거나, PDF를 다운로드 |
| **주요 기능** | • 주간업무일지 리스트 조회(제목/시작일/목표종료일/완료상태 표시)<br>• (관리자 전용) 부서 선택 필터로 전체 부서 조회<br>• 현재 조회 중인 목록 기준 PDF 다운로드<br>• **[신규 작성]** 버튼 |
| **다음 이동** | 항목 클릭 → 주간업무일지 상세 페이지, [신규 작성] → 주간업무일지 작성 페이지, [PDF 다운로드] → 파일 다운로드(같은 페이지 유지) |

## 🗄️ 데이터 모델

### departments (부서)

| 필드 | 설명 | 타입/관계 |

| name | 부서명 | text |

### profiles (사용자 프로필)

| 필드 | 설명 | 타입/관계 |
|------|------|----------|
| id | 고유 식별자 | UUID → auth.users.id |
| email | 이메일 | text |
| department_id | 소속 부서 | → departments.id (nullable, 온보딩 완료 전 null) |
| role | 역할 | text (`user` \| `admin`, 기본값 `user`) |
| created_at | 가입일시 | timestamp |

### weekly_logs (주간업무일지)

| 필드 | 설명 | 타입/관계 |
|------|------|----------|
| id | 고유 식별자 | UUID |
| department_id | 소속 부서 | → departments.id |
| author_id | 작성자 | → profiles.id |
| title | 제목 | text |
| content | 본문 내용 | text |
| start_date | 시작일 | date |
| target_end_date | 목표 종료일 | date |
| is_completed | 완료 여부 | boolean (기본값 false) |
| created_at | 작성일시 | timestamp |
| updated_at | 수정일시 | timestamp |

> `departments`는 초기 데이터(seed)로만 관리하고 별도 관리 UI는 MVP 범위에서 제외한다. `profiles.role`은 Supabase에서 수동으로 `admin`으로 변경한다(관리자 지정 UI 없음).
